Build systems like **Bazel, Maven, Gradle, Ant, Make, CMake** automate the process of building software.

Instead of manually compiling files, downloading libraries, running tests, and packaging applications, a build system does it for you.

### What a Build System Does

#### 1. Compiles Source Code

Converts source files into executable code.

Example:

* Java: `.java` → `.class`
* C++: `.cpp` → executable

#### 2. Manages Dependencies

Automatically downloads and manages external libraries.

Example:
If your project needs:

* Spring Boot
* JUnit

Maven/Gradle will download them automatically.

#### 3. Runs Tests

Executes unit and integration tests during the build process.

Example:

```bash
mvn test
gradle test
```

#### 4. Packages Applications

Creates deployable artifacts.

Examples:

* JAR files
* WAR files
* Docker images
* Native executables

#### 5. Handles Multi-Module Projects

Large applications may contain dozens or hundreds of modules.

Build systems determine:

* Build order
* Module dependencies
* Incremental builds

#### 6. Continuous Integration Support

Used by CI/CD tools such as:

* [Jenkins](https://www.jenkins.io?utm_source=chatgpt.com)
* [GitHub Actions](https://github.com/features/actions?utm_source=chatgpt.com)
* [GitLab CI/CD](https://about.gitlab.com/stages-devops-lifecycle/continuous-integration/?utm_source=chatgpt.com)

to automatically build and test code after every commit.

#### 7. Incremental Builds

Only rebuilds files that changed instead of rebuilding everything.

This significantly reduces build time.

## Maven vs Gradle vs Bazel

| Feature               | Maven       | Gradle            | Bazel       |
| --------------------- | ----------- | ----------------- | ----------- |
| Learning Curve        | Easy        | Medium            | Hard        |
| Configuration         | XML         | Groovy/Kotlin DSL | BUILD files |
| Speed                 | Moderate    | Fast              | Very Fast   |
| Dependency Management | Excellent   | Excellent         | Good        |
| Enterprise Java       | Very Common | Very Common       | Less Common |
| Monorepos             | Limited     | Good              | Excellent   |
| Large Scale Projects  | Good        | Very Good         | Excellent   |

---

### Maven

Best for traditional Java enterprise projects.

Common command:

```bash
mvn clean install
```

Used heavily in:

* Banking
* Enterprise applications
* Spring Boot projects

---

### Gradle

More flexible and faster than Maven.

Common command:

```bash
gradle build
```

Used in:

* Android development
* Modern Java backends
* Microservices

---

### Bazel

Designed for extremely large codebases.

Features:

* Distributed caching
* Remote execution
* Polyglot builds (Java, C++, Python, Go, etc.)

Originally developed by:
Google

Used by organizations managing huge monorepos and millions of lines of code.
